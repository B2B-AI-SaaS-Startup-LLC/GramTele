# План: полный порт AyuGram Desktop на Rust

Исходная точка — AyuGram Desktop 7.2.9 (коммит `0f2a31b`, TL layer 229).

## Объём

Портируется весь клиент: база Telegram Desktop, библиотеки Telegram и слой AyuGram.

| Часть | Строк |
|---|---|
| `Telegram/SourceFiles` (41 каталог, без вложенного sqlite) | 1 185 965 |
| Библиотеки Telegram (`lib_ui`, `lib_base`, `lib_rpl`, `lib_crl`, `lib_tl`, `lib_storage`, `lib_lottie`, `lib_spellcheck`, `lib_webrtc`, `lib_webview`, `lib_qr`, `lib_translate`) и `codegen` | 170 772 |
| **Всего: 3 892 файла** | **1 356 737** |

Не портируется только вложенный чужой код: ICU (заменяется крейтами `icu`) и sqlite (заменяется `rusqlite`).

## Правила порта

1. Структура модулей и имена повторяют оригинал: перевод идёт файл за файлом и проверяется по оригиналу.
2. Файл апстрима с патчем Ayu (их 183, помечены `// AyuGram`) переводится сразу вместе с патчем.
3. Ресурсы (`.style`, `lang.strings`, иконки, эмодзи, темы) переносятся без изменения формата; для них пишутся генераторы, выдающие Rust.
4. Форматы данных на диске (`tdata`, `ayudata.db`, `ayu_settings.json`) сохраняются байт в байт.
5. Улучшения и переработка архитектуры — только после паритета.

## Технические решения

| Что в оригинале | Чем заменяется |
|---|---|
| Окна и события Qt | `winit` + собственный слой `tg-window` |
| `QPainter`, `QImage` | Собственный `tg-gfx` с интерфейсом как у `QPainter`; растеризатор `tiny-skia` |
| OpenGL и RHI | `wgpu` |
| Шейпинг и раскладка текста | `parley` + `swash`; текстовый движок `lib_ui/text` портируется поверх них |
| `QString` | `String` |
| `lib_crl` | `tokio` + очередь главного потока |
| `lib_rpl` | Портируется как `tg-rpl` |
| `QNetwork*`, `QJson*` | `reqwest`, `serde_json` |
| OpenSSL | Крейты RustCrypto |
| ffmpeg, opus | FFI |
| OpenAL | `cpal` |
| rlottie | FFI |
| WebRTC, tgcalls, tde2e | FFI |
| hunspell | `spellbook` |
| Qt WebEngine и системные web view | `wry` |
| sqlite_orm | `rusqlite` |
| nlohmann/json | `serde` |

Исключение: HTTP-транспорт MTProto реализуется вручную поверх tokio AsyncRead/AsyncWrite из-за строки статуса Telegram с несколькими пробелами; reqwest в MTProto используется для DNS-over-HTTPS и HTTPS резервных конфигураций (special_config_request; разрешено пользователем).

Модель владения: граф объектов оригинала (`Data::Session` владеет всем, остальные держат сырые указатели) переводится в хранилища с типизированными идентификаторами; интерфейс и ядро живут в главном потоке, как в оригинале.

Циклы между каталогами оригинала (`data` ↔ `history` ↔ `api` ↔ `main`) в Rust между крейтами запрещены, поэтому ядро собирается в один крейт `tg-core`, а интерфейс приложения — в `tg-app`; внутри них модули повторяют каталоги оригинала.

## Этапы

Этап закрыт, когда выполнен его критерий готовности. Числа в скобках — строки оригинала.

### 0. Основа репозитория

- Workspace, сборка через Nix, CI, лицензия GPLv3.
- Реестр портирования: каждый файл оригинала с целевым крейтом и статусом.
- Эталонная сборка оригинала на исходной точке для сравнения.

**Готово:** пустой workspace собирается в CI, реестр содержит все 3 892 файла.

### 1. Фундамент (49 592)

- `tg-base` ← `lib_base` (26 846)
- `tg-rpl` ← `lib_rpl` (5 777)
- `tg-runtime` ← `lib_crl` (2 980)
- `tg-tl` ← `lib_tl` (868) и генератор типов из `api.tl`, `mtproto.tl`
- `tg-codegen` ← `codegen` (13 121): генераторы стилей, языковых строк, эмодзи

**Готово:** портированные тесты `lib_rpl` и `lib_base` проходят; сериализация каждого типа TL-схемы совпадает с оригиналом на наборе образцов.

### 2. MTProto (21 802)

- `tg-mtproto` ← `mtproto`: ключи авторизации, сессии, выбор дата-центра, транспорты TCP и HTTP, прокси SOCKS5 и MTProxy, CDN, конфигурация.

**Готово:** консольная программа проходит вход по коду и по QR на тестовом дата-центре и выполняет `help.getConfig` через каждый транспорт и прокси.

### 3. Хранилище (27 145)

- `tg-cache` ← `lib_storage` (4 598)
- `storage` (19 474): чтение и запись `tdata`, загрузка и выгрузка файлов
- `ayu/data`, `ayu_settings`, `ayu_state` (3 073): `ayudata.db` и `ayu_settings.json`

**Готово:** порт открывает `tdata` оригинала и подключается без повторного входа; оригинал открывает `tdata`, записанную портом; все 8 таблиц `ayudata.db` и все 124 настройки Ayu читаются и записываются без потерь.

### 4. Ядро (184 545)

- `main`, `data`, `api`, `core`, `lang`, `countries`, `apiwrap`, модель истории (`history.cpp`, `history_item*`)
- Обработка обновлений, мультиаккаунт
- Ayu в ядре: ghost mode по всем 10 настройкам аккаунта, `ayu_worker`, сохранение удалённых сообщений и истории правок, фильтры, `ayu/utils`

**Готово:** консольный клиент без окна показывает список чатов, получает историю, отправляет и редактирует сообщения, получает обновления; на записанных сценариях порт отправляет серверу те же запросы, что и оригинал, включая сценарии с ghost mode.

### 5. Графика и набор виджетов (185 259)

## Риски

- **Замена Qt.** `tg-window` и `tg-gfx` — работа сверх 1,36 млн строк оригинала; от её качества зависит весь интерфейс. Самые тяжёлые места: текст с IME и bidi, доступность, поведение окон на трёх платформах.
- **Блокировка аккаунта.** Неофициальный клиент с нестандартным поведением может быть заблокирован; все проверки идут на тестовом дата-центре и отдельных аккаунтах.
- **Дрейф апстрима.** Оригинал продолжает меняться; исходная точка обновляется только между этапами.
- **Нативные зависимости.** ffmpeg, WebRTC, tgcalls и rlottie остаются на C и C++, полностью на Rust будет только собственный код клиента.
